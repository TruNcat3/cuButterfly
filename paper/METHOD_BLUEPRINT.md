## 0. 从 Roofline 到可扩展组织

继承 APPT 的动机路径：W=BNL/2 次 pair update，若 G 段分别全量读写，value-only
流量为 2eBNG，强度为 L/(4eG)。逐 stage 物化的 G=L 为常数强度；只发生一次
必要读写的 G=1 给出随 logN 增长的理想强度。实际 Roofline 在明确的边界 h 使用
R <= min(P_pair, BW_h * W/Q_h)，其中 Q_h 是该边界的实际流量。不能把逻辑字节数
直接当 HBM 计数，也不能忽略系数、spills 与缓存。

减少物化会扩大驻留状态，因此 Roofline 的机会需与资源范围一起考虑。空间流水和
时间复用都可能保留数据；APPT 中特定 FPGA 的 II=1、流水整除和片上容量条件不
作为所有 GPU 的前提。实测历史例子印证组织价值，方法动机不依赖先测未来硬件。

可扩展性区分三个量：物化段数 G、逻辑递归层深、硬件实际存储层。限定每段完整
组件都由本地 leaf 执行，且 leaf 至多支持 k_max 位 stage，则 L <= G*k_max。
当 k_max=8，固定两段只覆盖 L<=16；L=24 至少三段，例如 8+8+8。这个界只针对
该受限两段实现，不说明任意两层 IR 都不能处理大 N。递归可以继续细分内部组织，
同时复用相同物理存储范围；不要求为逻辑 parent 的全域同时分配片上空间。

新增划分能力解决表达范围，实际速度仍取决于搬运、容量、核心与已有 lowering。
三个输入的分离使构造规则可复用；减少适配修改、采样和搜索的程度属于实验问题。
数学子图是分析单位；把它执行在 GPU 上属于下一层实现，不另立一个竞争的方法。

## 1. 从 stage 依赖构造闭合子图

对 N=2^L 的全 radix-2 蝶形包络，stage s 的配对索引为 i 与 i XOR 2^q_s，
q 是 L 个不同 bit 的有序排列。算术标签单独指定加减、twiddle、模数及数值契约。
取任意连续 stage 段，其 bit 集按执行顺序记为 Q=(q_a,…,q_b)，k=|Q|。

令 m_Q 为这些 bit 的掩码，a & m_Q=0，则对应索引集合为：

```
I(a,Q) = { a XOR Σ_j b_j 2^q_j : b_j ∈ {0,1} }
```

段内任何一条配对边只翻转 Q 中的 bit，因此不会离开 I。所有 a 对应的集合互不
重叠，覆盖 N 个索引；共有 N/2^k 个、每个 2^k 点的子图。这里的闭合指段内
依赖闭合，仍有段输入和输出。对单边 zeta 图，这个包络是安全覆盖，不保证最小。

分段为任意正整数有序分解 L=k_0+…+k_(G-1)，不固定 G 或 k。每段可进一步分成
更低层的子图：寄存器执行局部核心，共享内存保留较大图块，跨 CTA 使用合法的
全局交接。复用相同 worker 的多个图块是时间展开；实际独立资源上的图块才算空间
展开，不能将编译器 unroll 的阶段数当作物理流水级数。

计算核心必须实现该段的**带标签运算**和输入输出归属。FFT 不能随意拿一个完整
2^k 点 FFT 去替换任意全局 stage 段：需要正确的因子分解、跨因子 twiddle 和置换。
因此本例先用没有这些额外标签的 FWHT 展示组织，再讨论 FFT/NTT 的标签适配。

## 2. N=16：相同算术，三种组织

用未归一化 FWHT，pair(a,b)=(a+b,a-b)，stage bit 为 (0,1,2,3)。写 i=4r+c。
选择 2+2 时：

| 执行段 | 子图索引 | 局部变化 |
| --- | --- | --- |
| Q0=(0,1) | 固定 r 的 {4r,4r+1,4r+2,4r+3} | 改变 c 的低两位；四个行子图 |
| Q1=(2,3) | 固定 c 的 {c,c+4,c+8,c+12} | 改变 r 的高两位；四个列子图 |

每个子图用同一个四点 Hadamard 运算。第一段输出还按原逻辑索引标识；存储位置
可以变化。若两个段之间使用全局缓冲，四点 payload 的驻留只消除段内边界，不能
声称整个 16 点中间量在一个 CTA 里常驻。

以下为每个变换的解析值；element size e=4，只计值读写，不是实测 HBM 流量。

| 分段 | 物化组数 G | 逻辑值流量 2GNe | 单个闭合组件的数据 payload |
| --- | ---: | ---: | ---: |
| 1+1+1+1 | 4 | 512 B | 8 B |
| 2+2 | 2 | 256 B | 16 B |
| 4 | 1 | 128 B | 64 B |

payload 不是编译后资源需求。峰值活跃集还要包含并行组件、系数、预取/双缓冲、
中间寄存器和同步状态。最少流量的点可能因并发下降或 spills 而更慢，故必须同时
选择驻留范围和物理服务。一个图块也可能降低成多个物理组，实际流量按后者计算。

## 3. 布局从后继访问导出

pack(i,Q) 表示按 Q 的顺序提取并压紧 bit。选定 Q 的补集顺序后：

```
λ_Q(i) = pack(i,Q) + 2^|Q| pack(i,Q_complement)
```

它是对索引 bit 的置换，因而双射，且同一 I(a,Q) 连续存放。例中后继 Q1=(2,3)，
故第一段直接写 λ_Q1(4r+c)=4c+r；第二段从连续地址 4c+[0..3] 读，最终按逻辑
位置 4r+c 输出。一次独立的全数组 out-of-place 置换会增加 2Ne=128 B；直接写回
可省掉这个额外 pass，但写回自身的事务效率仍需评估。

这个构造给出后继连续性的候选，不保证同时优化 producer。producer 的 lane 归属、
shared staging 和写事务决定实际代价；原布局、直接对齐写回和显式置换都可参与比较。
共享内存用 bank/offset 映射，global 用事务/地址对齐，两者遵循相同逻辑交接原则，
物理代价不同。正文的单词 XOR bank 例子不自动证明 FP32 complex 向量访问无冲突。

## 4. 从依赖推导可流水的单位

第二段任意列 c 都需要第一段四行的各一个输出，因此只完成第一行时，任意一个
完整四点列子图都还不能开始。连续地址、已写部分值不等于完整输入已就绪。
依赖闭合的数据包由 consumer 的前驱集合决定。N=16 的多个独立 batch 可以交错；
大 N 内部的切片也可以交错，但要由各 stage bit 的依赖重新导出，不能假定任意
连续 CTA 区间都是闭合包。

此条件与大规模带来的 slack 并不矛盾：更多独立任务提供机会，容量、发布粒度、
资源供给与后继 fan-in 决定能否利用。保持理论层面的闭合条件，不把某个 backend
当前使用整 batch 事件的限制当作方法限制。

### 从两个 bit 集合直接求交接关系

令 producer/consumer 的变动位集合为 P/Q，规范基址 a/b 在各自变动位上为零，
全域掩码 M=2^L-1。两组件相交当且仅当：

```
(a XOR b) AND (M XOR (mask(P) OR mask(Q))) == 0
```

即它们在共同固定的位上取值一致。相交时恰有 2^|P∩Q| 个值；每个 consumer
依赖 2^|Q\P| 个 producer，每个 producer 服务 2^|P\Q| 个 consumer。
固定 P∪Q 之外的位得到 2^(L-|P∪Q|) 个互不相交的边界包，每包 2^|P∪Q| 个值。
在完整组件发布和全蝶形包络假设下，每包是一个完全二部依赖图，不能再拆成两个
无交接边的包。更细的子组件发布不受这个粒度约束，必须以更细单位重算依赖。
这里的包是依赖域，不是一次事务、一个 CTA 或必须同时片上驻留的分配；值可以
分布在多个 worker 和全局缓冲中，实际片上容量仍按生命周期与局部资源计算。

N=16 的 2+2 边界只有一包。N=64 的 2+2+2 第一边界有四包，按高两位区分；
下一边界也有四包，但按低两位区分。包数相同不等于成员相同，因此不可以把
第一边界的流水包直接当作贯穿全图的独立任务。这个例子同时说明大 N 内部的
独立工作机会，以及依赖分析为什么必须先于调度。

本轮 CPU witness 通过显式索引集合求交和独立图遍历验证这些关系，不用公式本身
生成预期邻接；范围 N=2..32，包含空、相同、相交和不相交的 bit 集合。

## 5. 预期效果：何时值得驻留和流水

物理组服务可写为 a_g+n_g b_g+z_g，启动、稳态服务和收尾都依赖核心、tile、
地址几何和资源状态。已包含在整 kernel 实测服务里的项不能再加一次。

在同一稳定资源区间，令 K 个独立包的非重叠与流水执行分别为：

```
T_bulk(K) ≈ A_b + (K-1) τ_b
T_pipe(K) ≈ A_p + (K-1) II_p
```

流水收益条件为 `(K-1)(τ_b-II_p) > A_p-A_b`。当 `τ_b > II_p` 时，更多包
可摊薄启动差；当共享带宽或串行依赖使 `II_p >= τ_b`，增加 K 不能消除稳态瓶颈。
这是两种局部服务近似的比较式，不是所有规模下的线性拟合保证。每包事件开销属于
II，不能全部算入 A；资源区间切换后要重新求服务。

II 至少受共享资源总工作量/供给率、依赖关键路径和 slot 重用约束。这个下界不能
直接当作一定可达到的性能预测。实际模型使用已校准的局部服务、调度开销及组合
假设，并通过未见完整配置验证相对排序。更快核心会改变资源主导项，从而可能改变
最优分段；核心可替换不代表核心和组织的性能互不影响。

## 6. 可复现的候选构造规则

| 规则 | 前提 | 动作与检查 |
| --- | --- | --- |
| 分段/合并 | stage 顺序固定 | 改变有序正整数分解；保留每段标签，推导闭合组件 |
| 核心绑定 | 核心支持该局部算术和归属 | 选择 core、数值模式及 tile；核对局部输入输出和同步 |
| 层次映射 | 有实际 GPU 资源可承载 | 指定并行/时间复用、驻留层、缓冲深度；检查峰值资源 |
| 边界布局 | 双方能表示同一逻辑值 | 选择 writer layout/consumer ownership；同时计读写代价 |
| 流式调度 | 前驱齐备、slot 生命周期合法 | 推导就绪包和重用边；串行与流水都保留为候选 |
| 排序/确认 | 具备 lowering 与服务覆盖 | 组合局部服务，有限预算下编译、正确性、screen、确认 |

规则解释现有分段、布局、核心、调度轴怎样组合，不宣称已经实现任意 bit-pack
layout 的通用 CUDA 合成。数学构造的覆盖、各 adapter 可生成范围、被预算实际测到
的范围必须各自报告。新功能只能通过实际 lowering 与测试增加，不能通过改稿增加。

CPU 实例：`python paper/tools/check_construction.py`。它检查所有 N=16 stage-bit
排列和有序分段的数学实现，并与独立稠密 Hadamard 参考比较；不测 GPU 或性能。

## 7. 正文简化后的变体推导备查

设 `R_L` 反转索引的 L 个二进制位，则
`R_L(i XOR 2^s) = R_L(i) XOR 2^(L-1-s)`。
位反转是位位置的置换，因此与 XOR 相容。它保持配对邻接，不自动保持连续访存。

局部 CT 和 GS 的矩阵分别是

```text
C(w) = [[1, w], [1, -w]]
D(w) = [[1, 1], [w, -w]]
C(w)^(-1) = (1/2) D(w^(-1))
```

要求 w 与 2 在当前算术域可逆。完整变换取逆还须反转因子顺序并处理输入输出
排列；L 个局部缩放累积为 N 的逆。浮点实现按对应精度的误差契约检验，不声称
bitwise 等价。zeta 的三角局部更新通过加减互换取逆，structured 矩阵另检查可逆性。
这些恒等式已有 `tools/check_theory.py` 的小规模独立检查，未新增 GPU lowering 声明。
