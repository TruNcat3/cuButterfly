## 2026-10-28 论证口径修正

中心问题是**并行组织范式如何兑现 Roofline 所揭示的资源机会**，不是单一的
并行供给不足。低于上界、规模变化后的收益趋缓，以及平台变化后的相对效率差异，
共同提出组织与资源如何匹配的问题；它们本身不唯一证明哪一种组织机制是原因。
用匹配核心的组织干预和资源分析检验解释。正文新增三个解析极限情形与一个
容量约束下的具体分段例子，示意图不冒充实测 Roofline。

已有 FFT 两核心×两组织的四格足够支持“这组收益不完全来自更换核心”。约
1.217×/1.221× 的固定核心组织收益前移为消融主证据。更强常规组织用于回答
剩余收益的大小，不再作为上述有限归因结论的额外门槛。FWHT/NTT 的负干预
仍保留，不能被写成每种机制在每类算子上必然有效。

本文与正文的关系分开：运行进度、未完成的采集及开发接口放在研究记录，正文
只保留研究问题、方法、实测证据、解释及适用边界。数值合同、负结果和样本范围
不能以“去开发化”为理由删去。新增趋势的来源和计算见
[本轮证据记录](evidence/ORGANIZATION_ARGUMENT_20261028.md)。

## 1. 真实研究路径和中心问题

用户回顾的起点是：不同领域反复出现相似的蝶形规律，却采用各自的性能优化方法。
进一步用架构视角分析时，单凭算术吞吐和 Roofline 中的复用机会，仍不能解释运行中
的动态表现及随规模变化的扩展行为。这促使研究转向局部计算核心之外的执行组织，
进而探索能否把这种组织方法推广到不同蝶形计算。
高效核心仍受不同硬件的访存、缓存、容量和并发约束。中心贡献是统一并行性能
范式，将依赖和时空组织需求连接到这些约束；已有专用库同样可以优化执行组织。

论文保留这条发现路径，但将个人探索经历转写成“问题—观测—解释—假设—验证”。
用户的研究回忆说明发现来源；每条公开性能观测仍须绑定具体数据。不能倒推所有
后来的实验都在最初发现时完成，也不能为了叙事而补造一条预期的扩展曲线。

**中心科学问题**：对于共享阶段依赖、但具有不同算术和资源需求的蝶形计算，能否
建立共同的时空组织性能表征，将容量、通信、计算与并行执行需求连接到硬件约束，
从而在保留专用核心的条件下跨算术、负载和平台选择高效组织？

**工作假设**：蝶形依赖能够提供共同的组织规则及资源需求表征。分层混合数据流
在阶段和数据两个维度组合空间展开与时间复用，将需求与具体核心、硬件的容量和
服务能力对接，选择不同的驻留、交换与映射。统一的是性能表征、构造和选择方法，
合适的设计点仍可因计算类型而不同。需求推导不等于精确运行时间预测；后者还需
物理映射、服务模型及实测验证。

“为什么值得统一研究”的主理由是共同结构可能产生可迁移的性能知识；减少重复
适配是需要另行度量的系统收益。不能把中心贡献缩成减少代码或统一 API。

## 2. 每一跳需要什么前提

| 前提与观察 | 因为—所以的连接 | 必须补上的证据或边界 |
| --- | --- | --- |
| 不同应用具有蝶形阶段依赖 | 因为配对与交接结构可以比较，所以值得询问哪些执行规律能共享 | 同一个小图换 FFT/NTT/FWHT 算术标签；说明系数、数值和方向差异。结构相似本身不证明性能收益 |
| 各领域已有成熟优化 | 因为局部算术与组织常共同决定实现，所以先区分两者的作用，检查优化能否跨领域复用 | 查证具体专用库、SPIRAL/FFTX 和通用编译系统的组织对象与复用边界；不预设它们只有核心优化 |
| 数据复用可以抬高资源上界 | 因为 Roofline 是上界而非完成时间预测，所以还要解释实现能多接近这个上界 | 相同边界的算术工作、实际流量与可持续带宽/核心吞吐；不能拿逻辑字节直接替代 HBM 字节 |
| 固定核心时，组织或负载改变仍影响实际效率 | 因为局部核心身份没有改变，所以完整性能差别需要从供数、资源与组织中解释 | 匹配条件的组织干预、N/B 扩展与 trace；低 occupancy 或低于 roof 本身不证明具体原因 |
| 更多驻留与更多就绪工作并不总能同时获得 | 因为容量、交接和并行供给相互约束，所以需要联合选择局部工作范围与时空展开 | 保留有利、接近持平和不利配置；固定优良组织与自适应组织对照，不故意使用欠填充基线 |
| 配对依赖可导出合法局部域与交接关系 | 因为这些关系可由依赖而非具体算术导出，所以可以尝试共同构造规则 | 闭合、边界、正确组合的推导与数值契约；FFT 段的系数/排列适配不能省略 |
| 共同规则需要覆盖变化的工作域和容量 | 因为固定局部容量有限，所以重复应用规则进行分层组合 | 先证明表达与容量合法性，再测性能；更多层级不自动更快，不等于增加物理存储层 |
| 规则被实现为公共生成与选择过程 | 因为实际调用确实复用了这些规则，所以可以检验统一后的性能与扩展价值 | 多核心组织对照、跨算术调用路径、留出配置与适配审计、有限预算选择和完整应用计时 |

三个关键措辞约束：

1. 写“Roofline 揭示资源机会，而其静态上界尚不足以决定执行组织”。不写“Roofline
   失效”，也不将观测到的任意低性能归因于新发现。排除缓存、系数流量、spills、
   核心效率、测量边界和时钟等替代解释后，才能收紧归因。
2. 写“组织是可独立干预的优化维度，但与核心资源及硬件存在交互”。不声称二者在
   性能上完全正交。固定核心不等于固定 wrapper、线程配置或整个 GPU kernel。
3. 写“共同依赖为复用提供条件，实验检验其收益”。统一不是逻辑上的唯一解，专用
   库也能采用相同组织；科研价值在可构造、可迁移的规律及其相对代价与效果。

Introduction 六段骨架，每段只承担一个推理动作：

1. 蝶形计算的重要性，以及不同算术下可辨认的共同阶段依赖。
2. 专用库已有很强性能；剩余问题是这种结构是否允许性能组织规律跨语义复用。
3. Roofline 揭示减少物化的机会，但驻留、就绪工作和交接使实际效率与扩展表现
   仍取决于组织。引用一个真实控制观察，而非在引言堆全部 profile 指标。
4. 因为固定核心仍能观察到组织作用，且相似约束跨算术出现，提出统一组织的研究
   问题。此处明确这一步是受证据启发的假设，跨算术有效性由后文检验。
5. 给出分层混合数据流的总体回答，并说明语义、负载、核心和硬件分别约束什么。
6. 概括贡献和证据，包括组织干预、跨算术/核心复用以及与专用库和应用的比较。

这不是增加一段背景后保持原稿不变。需要以新的因果句替换 Introduction、方法
开头和结论中重复的机制介绍，为动机的观测和对照留出篇幅。

## 5. 最小补足包及判定方式

### M1：把资源机会与实际运行连接起来

承接 E2/E3/E4/E5，先查历史记录是否已有匹配序列，再补缺项。对 FFT、NTT、FWHT
各保留一个已可审计的核心，在共同合法域中选两个中大型 N 和三个 B 档，覆盖启动
影响、过渡和较充分供给。点位依据容量和工作域确定，不能按胜负挑选。上限为
每类 2×3×3 个组织点、三类共 54 个配置，兼容旧点直接复用；不是新全量横评。

组织包括合理优化的常规分组、较深驻留和受约束的混合组织。若某组合没有合法
lowering，报告缺口；不能故意制造低并行基线，也不能假定更深驻留一定有利。
固定 N 扫 B 时保持核心与各组织配置，报告每元素/每变换时间及完整吞吐，区分工作量
增加与效率变化。N 扩展另成序列，保持局部核心定义，展示实际分段与布局变化。

每个算术先对一个依据假设选定的配置做两组织 trace，其他点只做普通计时。
记录完整调用时间、HBM/L2 字节、launch/交换、寄存器与 spills、活跃资源，以及
供数—计算—写回的时间关系。NCU counters 与系统时序各按其测量能力解释；硬件
统计是佐证，不能凭一个 stall 比例就认定根因。若未直接测到 tile 内 overlap，应
写未直接观测，不从 Graph 或 CTA 常驻推断已经流水。

Roofline 图按算术/精度分面，并声明分析边界。没有匹配的可持续 roof 测量时只画
符号上界和实际扩展曲线，不声称精确的“离 roof 百分比”。若单纯流量变化已足以
解释全部差别，应按数据收窄结论，而非坚持预设的动态供给解释。

### M2：证明组织规律可以复用，而不是仅能表示多类算子

承接 E3/E10。先用 CPU 审核一个公共组织规则在 FFT、NTT、FWHT 的实际生成路径，
记录共享模块、语义/核心适配、平台描述与隐藏例外。公共 API 相同不足以完成审计。
记录公共规则和适配边界。若论文需要参数泛化主张，再冻结构造器与选择规则，
选择现有合法范围内最多两个未参与手工特调的配置作参数留出，记录新增代码、
模型/搜索输入、编译结果、数值验证及有限预算性能；该项不作为排序算法验收。

若记录真正新增语义或核心的接入，保存实际补丁并区分新增 leaf、语义 lowering、
公共组织规则修改和平台规则修改。既有接入也可作为可复核案例，不必为论文新造
算子。配置留出只能称参数泛化；只有新增语义才能支持新算子接入结论。

交付一个紧凑的复用表与实例。报告公共规则修改量、适配模块、测量次数和准备耗时；
没有匹配开发记录就不声称节省了若干人天，没有同协议对照就不声称调优成本更低。
组织规则可以复用，不意味着算术性能样本可以无条件跨算术复用。

### M3：补齐核心与组织的交叉归因

承接 E2/E3，优先复用 FFT 完整四格。对 FWHT 和 NTT，先检查已有第二核心的共同
合法域，再各选两个代表请求补四格。按每个核心分别比较常规与混合组织；组织内
再比较核心。核心支持域不相交时如实保留缺口，不把不同 N/B 拼成四格。

机制干预与自动库表现分开：固定配置对照解释原因，同等预算重搜解释实际选择。
保存核心代码身份、全部 mapping 差分、种子与预算；普通独立复测确认入选方案。
机制负收益也是有效结果，检验选择器是否能识别其边界，不能因此无限追加优化。

跨硬件与完整应用沿用 E7/E13 编号；E7 的第二平台限定为待测的 RTX PRO 6000
Blackwell Server Edition 96GB，不为本叙事另开大矩阵。已有 A10040/80
同架构复现不能替代跨架构结论。未完成浮点验收继续按用户口径报告完整误差，不
自动采用新阈值；整数保持精确验证。

## 7. 执行顺序与完成边界

1. 已记录研究路径，并完成一轮正文因果链改写；当前动机采用 A10040 M1 完整对照。未补证据的
   位置保留假设与覆盖边界，现有性能分布和应用图的实测数值未改写。
2. CPU 阶段先整理既有数据的合同、核心身份和复用审计，确认 M1–M3 真正缺项，
   并预编译。既有 E 编号与队列不因叙事改稿重编号或重跑。
3. GPU 阶段只补所确认的匹配点与少量 trace，复用兼容完成记录；不以性能必须
   为正作为完成条件，不将本轮研究记录变成新的无界优化任务。
4. 接纳实测后重排图表与实验结论，再检查摘要—动机—方法—证据是否逐项对应。
   每条主张都应能定位到分析、受控结果或明确边界，不能只靠更多连接词补齐因果。

平台顺序为先收敛 A100 已定义的有限完整横评、消融、分析与应用清单，再执行
PRO6000 迁移和匹配比较。清单完整不等于无界笛卡尔积或必须全胜；历史排序竞赛、
模型留出和 regret 计划不再是必做项，也不作为平台迁移前置门槛。

M1 的固定干预是每个物理分组内的 shared/register 物化选择，不是完整混合数据流
搜索。其 local0 仍在物理分组内使用共享内存，不能称为每个 stage 经 HBM 的基线。
分组也改变寄存器所有权和活跃线程数；这属于本次组织干预的代价，不应从报告中去掉。
完整 54 配置现已生成六面板扩展图，展示三次独立计时的中位数和全范围，不填预测数据。
反复短任务干扰后，补测已改为逐请求封存的有限队列，每个请求仍包含三种组织、
三次独立计时和相同数值检查。已通过隔离检查的请求不因之后的打断重新执行，
每个原始 release 保留自己的身份，不伪造合并运行的身份记录。

在各算术的六个请求内，local2 相对 local0 的几何均值为 FFT 1.196×、FWHT
1.106×、NTT 1.199×；local4 为 0.932×、1.103×、0.816×。这些比值说明同一
标量算术原语周围的组织改变可以产生跨算术收益，也可以退化，不能写成相对 cuFFT
或 GPU-NTT 的提升。B 增加并不保证吞吐提高，原始波动也不支持把描述性均值称为
统计显著的收益。原始三次计时、分组和模块身份均在结果报告中。

九格匹配 profile 的实际 launch 均是两个 16384-CTA、256-thread kernel。
local2 未显示明确 HBM 流量减少；local4 在三类算术中均显著增加寄存器需求、
降低活跃 warp 比例并增加 barrier-stall 百分比。源码中交换边界减少，不能直接
推导实测等待减少。该证据支持物化、所有权和资源的联合权衡，但尚未唯一归因，
也不能从高寄存器数声称出现 spilling。普通计时与单次冷 profile 的排序差异同样保留。

M3 保留了一次配置生成错误：64 位 NTT 素数被 JSON 生成环境舍入为合数，原始
8 个 NTT 预检均失败，未获得性能数据。修正后按精确整数重新生成并完成 NTT 子集。
公共 controlled runner 已增加 CPU 阶段的整数类型、字长、素性与根阶检查，防止
相同错误再次占用 GPU。嵌套 mapping 控制也已贯穿请求与实际解析差分，避免只看
顶层标签便认为控制变量成立。51 项受影响测试通过。

正文目前加入实际复用边界、M1 完整扩展曲线及 M3 的负结果，保留历史正收益证据。这样形成的结论是
**共同依赖结构允许复用组织构造，但具体组织是否有利必须测量和选择**，而不是
“层次更多、驻留更深或时间分组更大就必然更快”。匹配 trace 用于进一步
区分组织的收益与资源代价，不能用这句定性解释替代尚未完成的测量。
这些机制负收益不等于 FWHT/NTT 的外部库横评落后；二者的对照、测量边界和
结论分别保留，不能用机制实验改写已完成的外部性能结果。

## 9. 性能表征与四节实验的收敛

最新正文将贡献收敛为“依赖结构 → 时空组织的资源需求 → 硬件约束下的优化”。
方法章明确阶段/数据两个维度各自空间展开、时间复用的代价，并用固定计算单元
预算的解析例子说明外部供数与内部通信之间的转移。空间展开可能增加计算单元、
状态与端口需求；时间复用可能增加反馈、状态寿命和执行步数。不能简单写成所有
时间复用都经过 HBM，或所有空间展开都只消耗缓存。

硬件约束是该表征的输入。只要相应资源、兼容核心和物理映射已被表达，就能在
约束下构造、排除和比较候选；这一能力不等于已证明任意硬件的最优性能。
组织效果的证据采用相同调优条件、合法性合同、真实 mapping 和独立确认，不能
仅由完整空间包含常规空间来推出。搜索是工程手段，撤回模型/结构/随机排序竞赛
和排序留出作为核心或必做证据；相关历史记录与负结果仍保留。

实验正文现为四节：设置；框架与高性能库比较（含应用）；消融（组件与核心×组织）；
生成算子分析（外部匹配 profile 与内部机制诊断）。主平台 A100 80GB，第二平台
为用户确认的 RTX PRO 6000 Blackwell Server Edition 96GB，第二平台结果待测。
有限补证、预算及接口缺口见[执行合同](experiments/hardware_characterization_closure_20261027.md)。
先收敛 A100 有限完整实验，再执行该合同的第二平台少量请求作为迁移试运行；正式跨平台横评仍须预定义并对齐共同
请求集合，不能用试运行替代跨平台性能结论。既有测量与后台队列未因改稿而改变。
