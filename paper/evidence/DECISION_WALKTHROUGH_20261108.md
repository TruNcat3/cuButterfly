# 从依赖构造到不同组织选择（2026-11-08）

本轮只重组已有 A100 证据，补齐方法章与消融章之间的推理连接，不运行 GPU、
不重开已关闭矩阵、不改变数值合同。PRO 6000 由用户独立推进，正文保留未测状态。
两个主贡献仍是依赖驱动的资源表征与分层混合数据流，搜索只是选择实现的手段。

## 同一构造得到的逻辑对象

来源为 [冻结端点证据](../generated/nonfft_endpoint_control_20261107.json) 的
`frozen.config.cells`、`frozen.resource_expectations` 与
`resource_formula_audit`；选择和独立复测同时收录于
[资源链导出](../generated/resource_decisions_20261107.json) 的
`prospective_measured_selection`。本表按已有方法公式重新计算，属于解析量，
不是新增计数器测量。

| 推导量 | FWHT FP32 | NTT word64 |
| --- | ---: | ---: |
| 请求 N / B | 65536 / 16 | 1048576 / 16 |
| 阶段分段 | 8+8 | 10+10 |
| 每段区域大小 `2^s` | 256 值 | 1024 值 |
| 每段区域数 `BN/2^s` | 4096 | 16384 |
| 每区域值字节 `e 2^s` | 1024 B | 8192 B |
| 每变换生产者 / 消费者区域数 | 256 / 256 | 1024 / 1024 |
| 同一变换内的生产者/消费者交集 | 1 值 | 1 值 |
| 每消费者的逻辑前驱数 | 256 | 1024 |
| 整个请求的独立边界包数 | 16 | 16 |
| 语义输入输出字节 `2eBN` | 8 MiB | 256 MiB |
| 两段值路径字节 `2eBNG`, G=2 | 16 MiB | 512 MiB |

两段的变动位互不重叠，且覆盖整个变换索引。同一变换内每对生产者和消费者
区域因此交于一个值，跨变换交集为空，固定 batch 索引得到一个边界包。
算术标签不同不改变这一依赖包络；
它仍决定实际算术、系数和合法数值语义。

这些数不能替代测得的外存流量、同时活跃值数或资源占用。原始
`logical_regions=2` 实际命名的是两段阶段，不是两个闭合区域。冻结字段不改写，
正文和 [资源证据说明](RESOURCE_DECISIONS_20261107.md) 已更正其解释。

## 从逻辑对象到物理候选

FWHT 两段分别启动。前段为 4096 个计算组，后段每组处理 1/2/4 列，对应
4096/2048/1024 个计算组。源码共享存储请求下界为前段 1 KiB、后段 1/2/4 KiB，
不把它当作完整编译器资源证明。前段直接写出后继读取的布局。两种线程数
128/256 和三种列分组构成每 leaf 六个候选；常规域保留其中两种单列候选。
逻辑读写量不随列分组改变，实际事务、指令和服务效率仍可能改变。

NTT 两段在一个 cooperative persistent launch 中执行，外存缓冲承接交接，
不要求整个变换驻留片上。`data_time=1/2/4` 是同一空间分组顺序访问的独立
transform 数，本文称 traversal group，不能称其合并成一个依赖边界包。
每 leaf 三个候选，原始 `data_time=1` 同时属于常规域与扩展域。
shared-r4 的动态共享存储请求为 32800 B；warp-r2 的动态请求为 0，后者不证明
全部编译器共享存储为零。实际 launch grid 受 occupancy 和目标组数约束，不能
由 `B/data_time` 或 16384 个逻辑区域推定。

逻辑前驱与实际发布单元也不同。shared-r4 的一个生产者计算组处理四行，因此
等待 256 次生产者发布；warp-r2 等待 1024 次。两者都等对应 transform 的
生产者完成，FWHT 的两次 launch 还采用更粗的全局顺序。这些实现没有把单个
区域交集当作独立发布点。源码定位见 `src/ntt.cu` 的
`hierarchical_streaming_10x10_kernel` 和 homogeneous packet-loop 路径；这些
说明来自已有源码与冻结审计，不是新的时间线或驻留度 profile。

## 有限选择与独立结果

资源描述和候选先冻结，再 screen，最后三进程独立确认已选映射，第二进程
反转顺序。共同预算上限是六个候选，实际候选池不同且全部接受并执行。
因此这组实验验证候选到执行的连接，不测量容量排除带来的收益，也不是数值
代价模型预测比赛。完整合同、设备/构建身份和冻结哈希见原始导出。

| 固定算术 leaf | 常规域选择 → 扩展域选择 | 三进程中位延迟 µs | 配对比值中位数 |
| --- | --- | ---: | ---: |
| FWHT radix2 | T128/列1 → T256/列4 | 60.447 → 45.875 | 1.317646 |
| FWHT radix4 | T128/列1 → T256/列4 | 59.894 → 43.878 | 1.365126 |
| NTT shared-r4 | T256/dt1 → 相同映射 | 1585.398 | 1（恒等） |
| NTT warp-r2 | T256/dt1 → 相同映射 | 3706.778 | 1（恒等） |

NTT 同一映射每进程只测一次，不存在两条独立计时臂。FWHT 改了线程数和列
分组，不能把收益全部归于列数；NTT shared-r4 的 dt1 为成熟专用 wrapper，
dt>1 为通用 packet-loop wrapper，不能把结果归于单独的遍历或驻留机制。
warp-r2 保持 wrapper 家族，但仍没有对应驻留/外存计数器支持瓶颈归因。
固定 leaf 表示算术实现不变，不是整个 kernel 的组织都不变。

所有 NTT 候选逐元素精确校验，十二个 FWHT 候选在这组输入的 2^20 个输出上
与 CPU FP32 参考一致。这不新设普遍浮点误差阈值。

## 对论文的支撑与边界

方法章的 16 点例子推导闭包、容量与交接，实验章在两个真实请求上复用同一
规则，再将逻辑对象接到实际候选和确认结果。FWHT 选择更宽分组而 NTT 保留
原端点，支撑共同构造下的条件性组织选择。已有跨算术局部组织实验仍独立保留，
其中 NTT 有正收益；本例的 1× 不代表 NTT 完整实现相对外部库没有收益。

层次化允许在有限存储范围内递归应用构造，不是一个必须开启的性能开关。
固定外层两段的组织实验不能单独证明更多层级总是更快，也不需要如此主张。

独立的 November 3 FFT/FWHT 服务组合研究提供后验预测一致性，绝不能与此处
实测选择合并成 NTT 前瞻数值预测。所有新增 NTT `cost_prediction_ms` 保持空值。
外部库比较、固定核心归因、资源解释和跨平台验证各自承担不同证据责任。

本轮更新方法、消融、分析的连接与术语，保留所有性能快照、表格数值、负结果
和原始构建身份。验证记录见 [VALIDATION](../VALIDATION.md)。
