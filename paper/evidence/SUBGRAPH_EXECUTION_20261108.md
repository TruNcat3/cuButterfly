# 子图执行的论述与证据（2026-11-08）

本轮只补论文中“依赖构造如何成为实际执行”的连接，使用已有测量，不新增 GPU
实验，不改变数据、数值阈值或 A100 冻结集合。此前“A100 足够”的说法应限定为
已有数据支撑有界的组织收益，不能替代这段论证，也不代表每个机制已被独立归因。

## 论述链

1. **可执行性。** 给定阶段带，依赖闭包包含局部操作的所有内部生产者；边界输入
   就绪后，局部操作可按依赖顺序执行。布局、发布和复用仍须满足正确组合条件。
2. **执行单位。** tile 子图将闭合区域绑定到核心、所有权、存储范围和交接。
   内部边留在选定范围，边界值按后继表示发布；子图不是一次库调用的别名。
3. **资源与规模。** 执行组可在一次 kernel 内连续处理多个独立 tile，按最终读取
   释放局部槽位。预取只扩大有界活跃集；整体变换与所有中间数据不必一起放入片上。
4. **预期收益。** 局部保留可减少外层交换与独立提交，但增加局部容量、端口和
   同步需求。收益由完整资源权衡决定，不能从“分组更深”直接推出更快。
5. **实验验证。** 固定叶核心后，比较完整执行组织；再用更强端点、不同算术和
   资源指标检查收益条件。跨大阶段 overlap、阶段内流水、worker 持续运行和数据
   驻留分别判断，不能互相替代。CUDA Graph 等提交图本身不证明局部数据驻留。

## 既有证据及限制

| 要说明的内容 | 已有证据 | 能得出的结论与限制 |
| --- | --- | --- |
| 实际执行闭合子图 | [四格实现](../../apps/cubutterfly_core_dataflow_ablation.cu)的 `resident_prefix_kernel`：256值tile，两个radix16步骤调用相同 `Core::run`，通过shared存储和barrier交接，再写回；[实验配置](../experiments/core_dataflow_ablation.json)保留后续全局边界 | 这是八个radix2阶段组成的具体prefix实例。旧“two-stage prefix”指两个radix16步骤，不是两个radix2阶段；它不证明任意子图都已有lowering |
| 子图组织收益并非只来自换核心 | A10080 FFT两核心×两组织，六负载、三试验、72计时行；组织GM 1.217/1.221×，固定组织换核心1.042/1.046×；[配对汇总](../generated/principle_core_organization.csv) | 固定leaf与目标变换，非固定整个kernel。所有权、线程、launch及wrapper改变，N256/B1为16/256线程；只能归因到完整组织干预 |
| 更强端点下的收益 | 独立FP64 N65536/B16双256点factor控制，预取相对强单tile同步端点为1.034/1.093×；[冻结记录](factor_organization_20261025.json) | 两侧已有factor子图模板和对齐交接，验证tile遍历/预取选择，不是又一组“有/无子图”实验；cuFFT仍更快 |
| 同一思路适用于不同局部算术但收益有条件 | 独立A10040诊断18负载、162观察，FFT/FWHT/NTT local2为1.196/1.106/1.199×，local4为0.932/1.103/0.816×；正文保留资源计数器 | 两个外部阶段带不变，改变内部局部交换，不是逐阶段外存控制。不同设备/cohort不混算；无shared-access计数，不能断言全由减少外存流量造成 |
| 原始端点仍是合法选择 | [强端点与资源链](RESOURCE_DECISIONS_20261107.md)：FWHT两leaf选择新组织，NTT两leaf保留原组织 | FWHT线程和列数同时改变，NTT部分wrapper不同；不支持所有算术都需要加深子图或开启流水 |

## 是否需要重开 A100

当前主张是“有界子图执行实现统一组织，固定叶核心下可取得条件性完整收益”。
该主张已有具体实现、正确性检查、配对测量、强端点与负结果支持，不因补这段
文字自动重开矩阵。若以后单独主张“驻留贡献了多少”“少launch解释主要收益”
或“流水保证掩盖交换”，需要对应的匹配控制；当前没有这些独立因果结论。
跨架构仍由用户在 PRO6000 上验证，不以本次文字修改替代。
