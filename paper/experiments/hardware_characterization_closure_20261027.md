## 目标与证据边界

检验时空组织的容量、带宽、算力和供给需求表征，是否能在平台约束下帮助自动
选择组织。分别回答外部竞争力、固定核心的组织作用和性能
原因；不能用统一 API 或适配 LOC 替代这些问题。平台校准与成本审计属于必要
上下文。搜索是工程手段，不作为核心创新；本合同撤回模型/结构/随机排序竞赛、
排序留出与 regret 作为必做证据。已有数据及原始负结果保留历史身份。

## 执行前冻结清单

每个请求保存完整语义、输入/种子、源文件及核心/二进制/模块 hash、硬件身份、
编译策略、计时协议、候选清单、拒绝原因、实际消费的 profile/registry/cache、
模型参数/训练来源、允许变化字段与解析后 mapping 差分。大整数 NTT 模数必须
以精确整数保留；沿用全 batch 精确预检，禁止浮点配置生成造成舍入。

核心冻结为算术 leaf 的代码、算法/radix、系数、存储/乘法/累加精度和支持域。
两侧组织空间先经实现/合法性审计：常规侧使用已有正常优化的原生组织或匹配
常规组织；混合侧开放已实现的分段、驻留、布局、空间/时间展开和供给选项。
两侧都允许合理调优，列各自合法候选数量、缺 lowering、资源拒绝、预算遗漏和
必要 wrapper/线程变化。单 stage 严重欠填充的旧控制不作为强常规侧。

开始测量前冻结以下预测及可证伪条件：组织如何改变活跃状态容量、必要/实际
交换量、算术工作与核心吞吐、独立就绪 tile/CTA 供给及交接开销。理论字节不等于
HBM 字节，逻辑 CTA 不等于实测驻留；静态约束通过后仍需编译资源与正确性确认。
保留模型/校准来源；若另行报告留出泛化，测试请求不得回填拟合后重报为零补测泛化。

## 下一批有限任务

以下是总上限，不做算子×精度×N×B×平台全笛卡尔积；先复用兼容记录。
其中 C5 的第二平台少量请求只作迁移试运行，不能替代论文跨平台性能比较。
正式比较另按预定义共同请求集合覆盖所报告算术、精度和规模，不按试运行胜负选点。
源/二进制、硬件或合同不匹配的旧记录只能作先验或历史分面。新构建仅补新增、
失效与最终入选点的必要确认，不机械重跑所有完成点。

| 顺序 | 有限输入与工作 | 交付/完成标准 |
| --- | --- | --- |
| C0 CPU 合同 | FFT/FWHT/NTT 各冻结1个现有可审计核心、1个既有中大型请求；从M1/M3合同核对真实支持域，不按胜负选点 | 三请求与两侧候选签名、核心身份、差分白名单、训练来源和接口缺口；不能合法比较者标缺格并停止该格 |
| C1 公平组织调优，E6/E9 | C0每请求两侧各最多16个 screen attempts，包含 seed、失败/拒绝后的实际尝试；采用相同调优条件与预定义随机种子 | 各侧最多3个 finalist，普通计时独立确认；保存合法性、真实 mapping、候选遗漏、失败及准备成本。不追加排序竞赛或4/8/16曲线 |
| C2 参数复用审计，E10 | 先核对M2建议的(logN13,B7)/(logN17,B19)的合法性与历史使用；最多2个完整请求，仅在需要支撑参数泛化主张时测量 | 记录公共规则与适配边界。若执行，沿用C1调优与确认协议；未经证实的留出不称泛化。排序留出不是A100收敛的必做门槛 |
| C3 固定核心交叉，E2/E3 | 复用已有真实第二核心；优先在C0的一个共同合法请求上增加核心B的同预算两侧比较，不扩所有算子矩阵 | 输出核心A/B×常规/混合四格、各核心内组织比值及组织内核心比值；缺第二核心、共同域或匹配常规实现即报告，不新增自研核心补空 |
| C4 外部配对分析，E1/E14 | 从已确认的C0请求中最多选FFT/FWHT/NTT各1个，公共最终方案与已核对契约的外部库配对；每对普通确认+NCU/NSYS | 双方同语义、输入、计时边界和目标卡；完整调用及各kernel可追溯，见下方指标合同。无匹配外部实现的算子标缺失，不替换成内部参考 |
| C5 第二平台，E7 | A100有限完整实验收敛后移植同一冻结合同、复用核心与构造规则；迁移试运行最多重复C0三请求及已执行的C2两请求，仅执行合法且外部实现可用的项 | 记录新平台约束/校准、映射变化、独立确认及准备成本；未知lowering/编译/库支持先列阻碍，不自动开发新实现或复制E1全矩阵 |

C2 的“两个请求”是两个完整语义请求，不将两个 tuple 自动扩成三算术六请求。
冻结时按已有能力和容量边界指定算术/精度，不依据测试收益挑选。C1/C2/C3
沿用受控运行器的三次独立进程、100 warmups/100 repeats 协议（若明确另定协议，
先冻结并独立标 cohort）；确认进程不复用 screen 样本。正确性/编译/初始化
在普通 kernel timing 外。浮点完整误差/既有验收未满足者只作诊断，整数全 batch
精确不通过者不接纳性能。独立确认必须绑定最终真实 mapping 和当前构建。

固定总 attempts 与成功测量数分别报告，不用增加可用候选数本身证明方法有效。
若现有公共路径不能强制核心或组织空间，C1/C3先输出缺接口，不把手工显式点
伪装为自动选择。组件禁用重搜只在C0中选一个已实现且有明确因果假设的组件，
同一总预算限制；组件开关与搜索选择是两种证据。

## 第四节的 NCU/NSYS 指标合同

外部配对为主要性能分析；M1/M3 另置“内部机制分析”。profiling前保存双方普通
独立计时，固定选点理由、请求/最终mapping、二进制与profile版本。记录NCU
replay/cache/clock policy与NSYS采集边界；按目标工具支持查询实际 metric 名，
缺指标写 unavailable，不猜版本通用性。优先同一operator-only范围，否则明确
拆出setup/输入输出/验证，禁止把整个进程拷贝当算子HBM流量。

| 需求/假设 | 观测量与汇总方式 | 能支持的判断及缺失处理 |
| --- | --- | --- |
| 容量与并发 | 实际grid/block、registers/thread、static/dynamic/allocated shared、local/spill读写、occupancy资源上限、活跃warps | 区分静态资源上限与观测活跃度；高寄存器不自动证明spill，未采local指标保留空缺 |
| 带宽与物化 | DRAM读/写bytes、L2读/写sectors与hit分母、shared事务/bank conflicts，按完整调用求和 | 与语义输入输出/边界理论量并列；缓存命中百分比或bandwidth百分比不能独自解释收益 |
| 算力与核心代价 | 算术/整数/访存指令、实际可采pipeline吞吐、issue效率及每完整变换工作量 | 外部内部算法未知即标未知，不能因语义工作相同就假定指令数相同；无匹配持续roof不报精确roof效率 |
| 供给、同步与时序 | NSYS launch/kernel/memcpy数量和绝对时间、空隙/同步/关键路径；NCU barrier/scoreboard等明确分母的等待指标 | 普通时间验证净收益；stall百分比不相加成总时间。tile内overlap未直接观测则不下结论，CTA常驻/Graph不替代测量 |

外部库多kernel时保留每kernel行及完整调用总量；百分比用原始分子/分母或明确
加权，不能简单平均各kernel百分比。分析先问流量、算术、资源、调用边界能否
解释观察，再讨论供给；若已有因素足以解释，收窄结论。外部实现允许具有相同
组织机制，不能把其内部未知写成没有。描述性计数器相关性不声称唯一因果。

## 接纳与停止条件

每项有可审计合同、完整正确性状态、真实mapping、预算与原始独立确认、明确
缺口和相应解释，即可完成一次有限实验，领先/持平/落后均接纳。不设必须全赢、
所有机制有效或全空间最优的通过条件。组织收益为负时保留结果、实际 mapping
与覆盖边界；机制退化不推导为FWHT/NTT外部横评落后，后者由匹配库对照决定。

缺第二核心、匹配外部库、目标硬件环境或受限搜索接口时完成准备审计并标缺项，
不能据此称整体性能主张已闭环。任何额外核心开发、全量矩阵和新应用集成另列
研究任务；本批负结果不自动触发无界优化。本文件及主计划未改变任何原始统计。
