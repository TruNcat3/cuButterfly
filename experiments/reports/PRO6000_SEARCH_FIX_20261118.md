# PRO6000 bounded search: stage-split coverage regression

A 16-candidate search selected scalar online-reorder [10,2] for FP64 C2C N=4096,
batch=1, while the existing [6,6] implementation was substantially faster. Trace
showed the original prefix launched only four blocks and consumed about 15 µs.
A repeat of the original search again omitted the balanced scalar split. This
identified finite candidate coverage, rather than cache replay corruption, as
a demonstrated source of loss. It does not establish incorrect hardware-rate calibration.

The fix preserves the incumbent and execution-organization coverage, represents
two-stage families using balanced splits before enumeration-order extremes,
excludes known unavailable FP64 direct-cuFFTDx candidates and CPU-projected
capacity failures, and allows rejected probes to be replaced up to a finite
four-times-budget attempt cap. The butterfly-family budget now counts successful,
correctness-checked measurements. NTT's separate protocol is unchanged. No split
is hard-coded to a GPU model, precision or transform length.

## New-build automatic search and replay

Both directions use fresh public MEASURE searches with budget 16. Each completed
16 accepted measurements in 16 attempts, with zero runtime rejections; capacity
projection excluded eight candidates before sampling. Both automatically chose
scalar online-reorder [6,6], radix2, 128 threads. Public DEFAULT cache replay
matched the selected mapping and original request semantics exactly. These are
new-build measurements, not replacements for the frozen Full66 or FFT17 rows.

The following comparison ran on **GPU0**, UUID
`GPU-1067ab39-e411-e141-1775-64426bca5701`, RTX PRO 6000 Blackwell Server Edition,
SM120. It does not mix timing samples with GPU1's original published cohort.
Old and new mappings were explicitly replayed in the same new library; GPU-FFT
uses its unchanged native SM120 provider and complete copy/reorder contract.

| Direction | Old mapping µs | New DEFAULT µs | GPU-FFT µs | Old/new | GPU-FFT/new |

Values are medians of three round medians. Each round has seven CUDA Graph
samples of 20 complete calls after ten warmups. Three rounds alternate backend
order within **one process**; they are not independent process trials or confidence
intervals. All original sample values and per-round results are retained. Plans,
compilation, allocation and CPU checks are outside timing; necessary execution
copies and normalization remain included. Guards passed before/after every
admitted timing record. Source inputs remain unchanged; Graph outputs reproduce
direct outputs byte-for-byte. Floating accuracy remains error-review-required.

Four additional N=256 B1 public MEASURE requests (FWHT FP32, subset/superset-zeta
uint32 and structured-2x2 FP32) passed execution and mapping-replay checks under
budget 4. Zeta outputs are exact; floating results retain their error reports.
These smoke cases do not replace a complete new-build matrix.
