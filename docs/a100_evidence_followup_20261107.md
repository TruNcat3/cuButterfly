# A100 论文补证收尾（2026-11-07）

本轮完成三项有界补证：资源表征到选择/确认的证据串联、主横评十个 FWHT 请求的原生返回公平对照、FWHT/NTT 的固定算术核心强端点控制。没有扩大工作负载矩阵或修改生产核心。PRO6000 Server 96GB 的跨架构验证由用户在目标机完成，本报告没有该平台实测值。

## 3. 固定算术核心与强端点

同为A100 80GB PCIe与775a库，GPU UUID为 `GPU-0eae5f07-33de-321b-70a9-ffeae49309e6`。所有请求自然序、正向、非归一化、out-of-place。FWHT为FP32 N65536 B16；NTT为word64 N1048576 B16，模数576460756061519873。两侧共同候选预算上限6，不为了填预算重复同一候选：FWHT常规/扩展合法池2/6，NTT1/3。

| 固定算术leaf | 常规设计点 → 扩展所选点 | 常规/扩展三进程中位延迟 μs | 独立paired比值范围 | paired中位 |
|---|---|---:|---:|---:|
| FWHT radix2 | TPB128、1列 → TPB256、4列 | 60.447 / 45.875 | 1.315401–1.317794 | 1.317646 |
| FWHT radix4 | TPB128、1列 → TPB256、4列 | 59.894 / 43.878 | 1.364784–1.367224 | 1.365126 |
| NTT shared radix4 | TPB256、dt1 → 同一配置 | 1585.398 / 同一次测量 | 同一配置 | 1（身份） |
| NTT warp radix2 | TPB256、dt1 → 同一配置 | 3706.778 / 同一次测量 | 同一配置 | 1（身份） |

FWHT概要为2阶段[8,8]—局部256点—前缀1子图/计算块、后缀1或4列—线程128或256—标量radix2/radix4—前缀直接写消费者布局。NTT为2个逻辑阶段[10,10]—局部1024点—cooperative producer/consumer单launch—线程256—每角色packet含1/2/4个transform—shared radix4或warp radix2—Shoup算术。逻辑阶段不是launch数，grid按占用约束确定，完整mapping在[冻结证据](../paper/generated/nonfft_endpoint_control_20261107.json)。

一次screen选赢家，三次独立guard进程只确认已选点，第二进程反转顺序。C++ event包围100次完整device调用，100次warmup；这是direct-launch，可能包含主机提交空隙，不与FWHT外部Graph计时混算。18个screen候选及每轮6个去重赢家均通过全16batch原校验；NTT逐元素精确。12个FWHT候选额外通过公共Plan对照全部1,048,576个FP32 CPU输出，误差均0，无新增阈值。

这里固定的是算术codelet身份，不是整个kernel。FWHT同时调优线程数与列分组，因此1.318/1.365不能单独归因为列数。radix4确实选择不同模板，把相邻两级合入四值寄存器codelet，保留相同FP32加减依赖树；二者是仓库内部实现，不是从两家外部库导入的核心。该路径top-level是scalar，通用派生`group_cores`标签不能替代实际分派身份。NTT shared的dt1保留成熟特化wrapper，dt2/4为泛化packet wrapper；warp路径保持其自己的wrapper。本轮没有新增NCU，旧trace不冒充当前构建的profile。

原M3固定配置负结果不撤销。新结果说明在本次有限域中，FWHT有固定核心下的组织收益，而NTT应保留原有端点；不需要把每个扩展维度强行展开。

## 4. 论文结论与复核入口

本轮强化的是“共同资源表征、可调整组织、固定核心下的条件收益”，同时收紧FWHT外部竞争力结论。A100证据不能写为所有接口/算子全面领先。NTT定量服务预测、完整跨架构验证仍有独立边界；PRO6000工作没有被这批A100数据代替。

正文已补两个紧凑单栏表，分别列出资源组合确认与固定核心强端点结果；外部FWHT段落及引言并列披露两种接口结果。历史主表、旧负结果、浮点误差政策保持可追溯。CLAIMS同步限定证据覆盖。
