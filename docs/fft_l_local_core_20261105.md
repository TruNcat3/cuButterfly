# FFT-L 局部核心接入与验证

2026-11-05。此记录属于 cuButterfly 开发验证，不能替代完整自动库横评。

用户所说的“原本核心”是用于调度子图的高性能局部计算核心，不是完整
cuFFT 调用。局部核心的原始单段点应保留，并与同核心的分段组织公平比较。

## 确认的缺口

- 精度、累加方式、方向和归一化已贯穿请求、模型键和缓存，并非丢掉精度。
- register/cuFFTDx 高性能局部核心的旧接入限制在 FP32/FP64，低精度测量实际
  使用 scalar 核心。因此旧 FFT-L 负结果不能表述为已经搜索过这些高性能核心。
- 本地 MathDX 支持 FP16；其 `Precision` 类型列表不支持原生 BF16。
- FP16 使用 `complex<half2>` 打包两条独立变换，不能沿用 FP32 的单变换几何。
- 公共构造器还有一个针对旧预编译核心的 N≤1024 上限，曾阻挡已生成的 FP16
  单组核心。已限定该检查的适用范围，实际资源仍由生成模块检查。

## 本轮实现边界

新增 FP16 cuFFTDx 单局部组 lowering，接入公共候选、独立模块编译、调用、
编译资源、物理几何和缓存身份。核心支持表、EPT 与线程几何联合筛选候选，
奇数 batch 屏蔽缺失 lane，不改变语义 batch。搜索预算的蝶形 family key
现在包含核心身份，避免不同核心因组织参数相同被混为一个 family。

当前公共接入范围为 native FP16 的正变换及未归一化逆变换。模块内部实验入口
可以做最终一次 FP16 归一化，但公共选择暂不使用该方式代替现有逐阶段归一化，
其范围和舍入行为还需专门验证。BF16-native、显式 FP32 compute 尚未完成。
较大变换的配对子图多阶段 adapter 已在后续本轮接入，见本文最后一节。
安装模板和编译依赖同时更新。

原 scalar 核心还新增编译期归一化分支，保留算术顺序和逆变换范围保护。
正向/未归一化逆向不再携带不执行的归一化条件。该修改不改变计算核心类别。

## 已有结果

A100 80GB，FP16 native 正向 C2C，N=4096，同一输入与完整调用的 CUDA Graph
计时，编译/创建 plan 不计时。以下 cuButterfly 两列为显式固定 mapping，
不是自动搜索已收敛的声明。cuFFT 为匹配存储/变换语义的 vendor-native 对照，
不声称其内部逐原语舍入与另外两列相同。

| batch | scalar R4，μs | 新 cuFFTDx 局部核心，μs | cuFFT，μs | 原 scalar / 新核心 |
|---:|---:|---:|---:|---:|
| 5 | 10.803 | 9.267 | 6.246 | 1.166× |
| 2048 | 161.946 | 80.998 | 47.923 | 1.999× |

新核心设计点为 **1 阶段—tile 4096—每计算块 2 条独立 FFT—256 线程—EPT16—
cuFFTDx FP16 half2**，B=5/2048 分别启动 3/1024 个计算块。scalar R4 为每块
1 条 FFT，256 线程。收益在这里来自核心更换及其固有配对装载，不是固定核心
下的混合数据流消融。与 cuFFT 的差距仍存在。

同精度 CPU 参考相对 L2 误差分别约为 scalar 0.001075、局部核心 0.002446、
cuFFT 0.001760；两种 batch 相同，因为复用同一输入行并核对所有输出 batch。
全部输出有限，误差仅报告，不新增浮点通过阈值。

归一化分支修复的独立配对实验，在 N4096/B2048/T256 下，R4 正向的 FP16
由 180.480 降到 161.434 μs，BF16 由 223.181 降到 162.304 μs；R2 基本不变。
配对输出逐位相同。该组输入和计时采样独立，不与上表拼接计算收益。

验证覆盖包括两个 N 的各 128 个独立模块组合，奇偶 batch、stride、原位、
方向与模块归一化分支；脉冲精确，随机误差另存。旧 scalar 的特殊数值边界
回归逐位差异为零。公共入口已验证 FP16 单段执行及 Graph 重放。

随后以公共 MEASURE 路径、16 候选预算验证 B=5 与 B=2048，两次均选中
`cufftdx-block/T256/EPT16`，Graph 延迟分别为 9.318 和 81.101 μs。
每次 16 个实测候选均通过已有运行检查。B2048 的完整枚举有 173082 个候选，
本次没有穷举，因此这里只证明该端点已进入公共搜索并被选中。
两个自动结果保存为 `public-local-core-b*-measure.json`，逐候选证据保存在
`public-search-b*.jsonl`。自动结果来自最后的诊断构建；前述显式对照保留各自
原始库哈希，不能改写为另一次构建的新测量。当时尚未替换共享 conda 库，后续新构建安装验收见本文末尾。

## FP16 多阶段接入与访存优化

同日后续实现将配对核心接入原有 `factor-streamed` 模板，复用全局数字旋转、
写出对齐、阶段内 tile 循环、预取及依赖闭合切片。逻辑列数与物理线程分别
计数，每个 half2 lane 对应一条独立 FFT。跨因子复数乘法保持 FP16 原语舍入；
旋转因子相位在 FP32 中生成后转为 FP16，避免把大索引先转成 FP16 导致溢出。
这不是将全部输入驻留在片上，也没有将两个物理 factor launch 描述为一个核。

局部单组入口另增加对齐的 32 位复数装载/写回；仅两字节对齐的地址仍走原有
16 位分量路径，奇数字节地址明确拒绝。两种入口的编译资源均参与资源检查。
该优化不改变 FFT 算术。旧/新模块配对测量的 N4096/B2048 中位数从
83.149 降到 58.522 μs，输出逐位相同，提升 1.421×。另两组 N4096/B256、
N8192/B256 为 1.047×、1.060×。公共入口重新测量分别为 12.083、58.573、
26.470 μs，对应 cuFFT 为 9.882、47.872、21.658 μs，局部单段仍有差距。

### 大尺寸结果

下面六组来自同一诊断构建的 76 项候选/基线测量，32 个独立模块均提前编译。
计时为每图 20 次完整调用、7 次重放、10 次预热；CPU 参考、编译和 plan 创建
不计时。cuButterfly 列为有限候选集中的实测最佳显式配置，不能替代 AUTO 排名。
加速比为对照延迟除以 cuButterfly 延迟，大于 1 表示更快。

| N | batch | cuButterfly，μs | scalar，μs | cuFFT，μs | 相对 scalar | 相对 cuFFT |
|---:|---:|---:|---:|---:|---:|---:|
| 16384 | 64 | 23.245 | 40.448 | 18.688 | 1.740× | 0.804× |
| 16384 | 512 | 114.176 | 202.752 | 104.192 | 1.776× | 0.913× |
| 32768 | 32 | 24.115 | 90.010 | 18.176 | 3.732× | 0.754× |
| 32768 | 256 | 118.067 | 308.890 | 106.957 | 2.616× | 0.906× |
| 262144 | 4 | 26.061 | 65.587 | 25.600 | 2.517× | 0.982× |
| 262144 | 32 | 145.459 | 375.040 | 155.597 | 2.578× | 1.070× |

设计点如下。C 表示每个输入组的逻辑独立 FFT 数，T 表示每块连续处理的输入组数，
D 表示预取的未来组数。所有点 EPT=8，核心为 cuFFTDx FP16 half2。

| N | 物理阶段与局部 tile | 各阶段线程 | C | 小 batch 最佳组织 | 大 batch 最佳组织 |
|---:|---|---|---:|---|---|
| 16384 | 2 阶段，128 → 128 | 128 → 128 | 16 | T1/D0，动态寻址 | T4/D1，展开寻址 |
| 32768 | 2 阶段，128 → 256 | 128 → 256 | 16 | T1/D0，动态寻址 | T4/D1，展开寻址 |
| 262144 | 2 阶段，512 → 512 | 256 → 256 | 8 | T1/D0，动态寻址 | T4/D1，展开寻址 |

同核心、同 factor 分解、同列数下，大 batch 的 T1/D0 延迟分别为 171.366、
179.763、192.717 μs；T4/D1 加展开寻址后分别获得 1.501×、1.523×、1.325×
提升。这支持阶段内组织机制的价值。单纯增大 T 而不预取的 T4/D0 反而更慢，
因此不能把最大可行 tile、最大 T 或开启所有机制等同于最优配置。原 scalar
对比同时更换了核心及组织方式，不是固定核心消融。

两组大 batch NCU 对照显示，factor 核使用 96–128 个寄存器/线程，约
14.6–17.5 个活跃 warp/SM；cuFFT 为 32–48 个寄存器和约 35–58.8 个活跃 warp。
部分 factor 同时受到寄存器和共享缓存的驻留块数限制，降低寄存器并不保证
增加驻留块数。N32768 两边均为两次核调用，cuButterfly 仍慢约 10.4%；
N262144 的 cuButterfly 为两次调用、cuFFT 为三次，较少的中间遍历可能抵消
局部核心的吞吐劣势。这是基于 trace 的解释，不是对闭源算法的确证。
详细计数及局限见 `results/a100_fp16_factor_20261105/performance/ncu_analysis.md`。

### 验证与剩余边界

- FP16 factor 完成 56 项结构/执行验证：三种 N、正向及未归一化逆向、原位与
  非原位、非连续 stride、不同预取深度及切片串行/重叠。脉冲精确，guards/gaps
  保持不变，同算术不同调度输出逐位相同。随机 CPU 相对 L2 为约
  0.001686–0.002251，浮点误差仅报告。
- 局部 I/O 两种 N 各完成 288 项旧/新一致性和地址合同检查，覆盖奇偶 batch、
  stride、地址偏移、两方向及模块内部归一化。输出逐位一致。
- 76 项大尺寸性能记录全部输出有限；最佳 factor 的 CPU 相对 L2 约
  0.001926–0.002253，cuFFT 为约 0.001820–0.001981。不设新的通过阈值，
  不声称两者内部舍入合同相同。
- 原有 FP32/FP64 factor 路径完成 16 项回归，含正向、归一化逆向、动态和展开
  寻址。脉冲精确、guards 完整、重复执行及两种寻址输出逐位一致。同精度 CPU
  参考最大相对 L2 分别为 2.44e-7、4.40e-16，记录于 `fp32_fp64_regression/`。

原始数据位于 `results/a100_fp16_factor_20261105/`，分别为 `correctness/`、
`performance/`、`io-public/` 及 `io-paired-1793884080286442607/result.json`。
`build/receipt.json` 记录诊断库及受影响对象；该诊断阶段没有替换共享 conda 库，后续安装验收见下文。
结论仅限 native FP16 的上述执行路径。下述有限服务校准和公共验收已完成；新 provider 的
归一化逆变换和其他低精度 provider 仍是后续工作，不能据此宣称 FFT-L 已全面领先。
