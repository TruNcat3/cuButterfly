# 2026-10-13 CUDA Graph 应用复测

本轮修复完整应用的 Graph 接入，保留已经测量的弱势点，并增加两个有限的
FFT 应用流程。Graph 是所有后端一致的主比较模式；普通调用仍保留在原始
报告中作为诊断。没有更换 cuButterfly 核心构建，也没有重新混合旧版本算子成绩。

## 已修复的 Graph 集成

图像滤波对 Torch、cuButterfly 和 CuPy 捕获相同的完整流程。CuPy 的捕获
临时地址原先可能被普通显存池复用，导致后续回放或已返回的结果遭到覆盖。
修复使用独立、随 Graph 存活的捕获显存池，普通返回值另行分配。验证覆盖
改变输入、恢复原输入、不同结果确实变化，以及旧结果在后续回放后保持不变。

新增 Poisson 求解还逐元素验证 Graph 与同后端 eager 输出完全相同。
相位相关配准验证返回位移与同后端 eager 及已知整数位移完全相同；完整相关图的
CPU 误差是另行测量的诊断，不冒充 Graph 返回了整个相关图。

QuaRot 的捕获检查、固定长度 cache 元数据和私有扩展流兼容性分别修复。
原扩展的量化、KV-cache 和 GEMM 有 9 处提交没有使用 PyTorch 当前流。
最小量化用例显示，原扩展虽然能够结束捕获，回放却没有执行量化 kernel。
隔离版本将这些提交接入当前流，最小用例回放与原扩展正常执行逐元素一致。
没有覆盖旧安装，双方应用都使用同一个隔离扩展。完整 7B 随机权重模型的
Graph 结果进一步对同后端 eager 核对，原输入和改变后的输入，两个后端
各 33 份 logits 均通过现有逐元素一致性检查。

可复现补丁是 `experiments/workloads/e13/quarot_current_stream.patch`，由
`build_quarot_graph_extension.py` 从固定源代码准备隔离构建。

## 为什么增加这两个流程

相位相关配准使用固定参考图的频谱，对每批移动图执行 FFT、交叉功率谱、
逆 FFT 和峰值归约。这对应
[scikit-image 的 Fourier 配准流程](https://scikit-image.org/docs/stable/auto_examples/registration/plot_register_translation.html)。
本实验限定整数循环位移和随机图，验证实现与性能，不声称验证自然图像质量或亚像素配准。

该流程虽然包含完整 FFT 对，但 CuPy 峰值归约成了主要瓶颈。2048²、B=16
的一个 trace 中，该归约约 7.475 ms；因此相对 CuPy 的大幅加速不能归因于
蝶形组织。相对 Torch 的结果仍在略低于持平至小幅领先之间，不能只引用较大的数字。

周期 Poisson 求解直接执行 `-Laplacian(u)=f` 的频域解法，流程是 RHS FFT、
乘以预先生成的逆特征值、逆 FFT 并返回完整解场。零频设为 0，输入先减去均值，
域为 `[0, 2π)²`。这类逆 Fourier Laplacian 用于
[JAX-CFD 的流函数求解](https://github.com/google/jax-cfd/blob/main/jax_cfd/spectral/utils.py)。
本次测试的是完整 RHS-to-solution 求解，不是完整 CFD 时间推进器。
两个不同随机 RHS 批次用于计时，已知 Fourier 模态用于附加正确性诊断。

## 瓶颈的直接证据

图像滤波 trace 中，cuButterfly 的 FFT 核心加已识别的 FFT 内部转置和归一化
约占 GPU kernel 累计时间的 74%，Torch 约占 72%。因此已有滤波场景本身就
能体现变换组织的收益，其约 7%–10% 端到端收益不是 Python 调用时间推算出来的。

更大的二维请求仍有具体 lowering 缺口。2048²、B=16 的 Poisson 首轮，
Torch 在相同 `regular_fft<2048>` 类型上共执行 2 次，而公共选中的
cuButterfly `xd-compact-r2c/c2r[strided-axes]` 对每个 batch 分别执行前缀轴，
共 32 次。同一个 trace 中这部分累计约 1.047 ms 与 1.617 ms。
实数/复数边界核心时间接近。Graph 降低主机提交成本，但不会自动把这 32 次
设备执行合并成 2 次，也不会自动改善每次的访存组织。

报告保存了公共运行时 Graph 计时选择、候选及淘汰原因。这不是“没有搜索”
或者再次校准即可解决的证据；当前可生成候选的跨 batch 轴映射和核心效率仍需改善。
下一次优化应针对这个有 trace 支撑的执行差异，保留相同请求复测。

Poisson 的第一个进程中，FFT 核心本身约占 Torch 的 kernel 累计时间 61%–63%，
cuButterfly 为 71%–75%；归一化等变换内部操作还在其外。这验证了新增流程
比带昂贵峰值归约的配准更集中于变换，但占比高并不自动保证我们的实现更快。
