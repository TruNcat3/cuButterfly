# cuButterfly 研究与论文状态（2026-11-04）

本次整理复用已有实验记录，没有启动新 GPU 测量。当前论证已经包含共同依赖、资源需求、分层混合数据流、子图执行及边界交接，以及外部横评、固定核心控制和应用结果。**已支持 A100 上有界的组织收益与库竞争力，尚不支持所有精度/负载全面领先或跨架构验证完成。**

## 已有性能证据

加速比统一为对照完整调用延迟除以本库延迟。每个集合独立统计；不同构建、精度、平台和计时协议不合并成一个总均值。

| 主横评 FWHT FP32 | DaoFHT | 1.474× | 原集合；不意味着逐点领先 |

## 本轮增加的机制证据

- **组织收益与核心替换分开。** 原FFT双核心控制约1.22×的组织收益仍保留。新增FFT-L确认固定局部算术后，边界组织可以改善；B4的BF16轻微负结果同样保留。
- **单段是合法端点。** FP16的N4096、B256单段radix4为33.59 μs，分组两段39.83 μs；N8192、B32则两段19.35 μs，单段32.36 μs。最佳组织取决于请求，不能以“大batch必然更多分段”解释。
- **物理指标连接实现与效果。** 独立A100 40GB的两段NCU显示各段store sectors/request从32降至4，算术指令计数不变，总warp指令34.32M降至11.48M。部分共享存储bank冲突仍升高；这不是HBM流量减少8倍，也不证明所有访存已最优。
- **理论、实现和选择分开。** 依赖交集给出传递值和前驱，实际访问组/字宽/存储端口约束物理布局。布局改善不要求强制分段，扩展因子为1同样属于方法空间。

## 论文已更新内容

正文保持实验设置、性能比较、受控组织实验、生成算子分析四节。FFT-L作为FP16/BF16精度列进入统一横评，独立机制图已移出正文。只有已完成的FP16公共选择重放进入图表，BF16及完整重测待测；固定配置留在证据包，边界profile归入通用分析。FP64/FWHT弱点继续保留，不改变原主集合统计。压缩了部分应用历史和重复的动机数字。引言不再将相同理想强度当作相同实际资源上限；方法区分依赖推导、编译资源和实测服务，并保留单段端点。

[论点评估](../paper/evidence/PAPER_ASSESSMENT_20261104.md)记录剩余问题。当前最有力的贡献是从共同依赖构建组织和交接、表征资源需求，再在硬件约束内选择实现；搜索算法不单列为贡献。

## 尚未完成

1. FFT-L最新修复版已通过48项CPU与144项GPU结构回归，但新阶段校准仅保存212条有效样本，34配置中已描述11个。GPU占用耗尽本轮1800秒等待窗口，队列已保存并停止；22请求规模和32请求语义重测尚未开始。不能把旧性能重标为新构建。
2. 新FFT-L共享环境安装与模型发布未完成。最近三请求FP64/FWHT的历史安装验收属于11月3范围，不等于本轮低精度迁移完成。
3. PRO 6000 Server 96GB仍待A100收敛后执行。A100 40/80GB的独立实验不替代跨架构结论。
4. “表征→资源与服务→选择”的实例还应与最终FFT-L实测衔接。当前可说明组织取舍，不能宣称完整空间已校准或有限搜索保证全局最优。
