# cuButterfly 设计与实验原则

本文件固化项目的研究目标与证据口径，适用于整个仓库及所有蝶形算子，
包括 FFT、NTT、FWHT、subset/superset zeta、结构化蝶形，以及之后新增的
算子、正逆形式和多维组合。它不是 FFT 专项优化规则，也不是某次实验
已经完成的声明。具体架构定义继续以 [蝶形设计空间](butterfly_design_space.md)
为准；本文件规定如何实现、验证和表述这一方法。

## 1. 研究目标

从蝶形计算的依赖关系出发，建立可复用的**分层混合数据流方法**，解耦
算子语义、负载规模、局部计算核心和硬件映射，自动生成并选择高效实现。
块级子图执行与驻留执行是方法的落地形式。具体分段、驻留层级、布局、
核心和流水方式是设计点，不能反过来限制方法只能使用固定两层或固定分段。

研究要验证两项不同的主张：

1. **方法统一性**：不同蝶形能通过共同的依赖表达、组织参数、生成与选择
   接口实现，不依赖为每种应用另造搜索流程。
2. **性能有效性**：根据算子、负载和硬件选择合适的机制组合，使各类蝶形
   的完整实现相对匹配的高性能对照获得收益，并使收益传到实际应用。

机制允许有适用边界。某种核心、overlap 或驻留深度不必对每类蝶形都
有收益。关键是空间能表达合适的组合，生成器能正确实现，选择器能
识别有利与不利的组合。统一表达不自动保证有限预算下找到全局最优，
也不自动保证胜过设计空间之外的外部库；这些属于需要实验验证的目标。

**外部竞争力与方法归因分别取证。** 保留 cuFFT 等高性能库的完整对照，
报告接近、领先和落后的适用范围，但不把逐点胜过闭源库作为统一方法成立的
必要条件。固定可审计局部核心、只改变执行组织的配对实验，才直接检验组织
收益；再跨核心和跨蝶形重复，检验复用能力。外部性能接近也不自动完成这些
因果论证。研究优先补齐这条证据链，不为追逐单个闭源库的全部点无限扩展优化。
引用相关工作必须限定其已报告的范围，不使用“以往无人达到 cuFFT”之类未证实
的前提。在仓库中实现的可审计核心须如实标注，不能冒称复用了某个开源库的核心。

**大阶段同步与阶段内流水分开判断。** 下一大阶段等待上一大阶段的全部
tile 完成是合法组织，不构成方法缺陷。阶段内可以让驻留执行单元连续处理
独立 tile，并按可用资源交叠供数、计算和写回；不要求每个子图重新 launch。
生产者直接写出消费者需要的布局，是这一组织的组成部分。跨大阶段或外部
batch 的 overlap 是额外选项，关闭它不能推断阶段内无流水。须分别记录
子图内部数据驻留、CTA 连续消费 tile、显式异步预取以及硬件调度隐藏延迟，
不把这些概念互相替代，也不把缺少双缓冲单独当成性能瓶颈的证据。

## 2. 设计原则

| 层次 | 应负责的内容 | 实现要求 |
| --- | --- | --- |
| 算子语义 | 运算、方向、归一化、精度/累加精度、有限域参数、输入输出顺序 | 用户请求原样贯穿前端、lowering、校验和报告 |
| 负载 | 各轴点数、rank、batch、布局、stride、placement | 作为可组合维度，不以算子名称分出隐藏特例 |
| 组织方法 | 分层、空间/时间展开、分段、驻留、交换、流水与 overlap | 机制可组合、可关闭；保持合法依赖和资源约束 |
| 计算核心 | 局部 codelet、算术算法、radix、系数表达及局部交换 | 通过明确接口替换，声明支持域与数值语义 |
| 硬件 | 容量、并发度、带宽、延迟、资源与平台规则 | 通过硬件描述、校准及平台特调接口提供，不散落型号分支 |
| 生成与选择 | 候选构建、代价估计、搜索、编译、缓存与调用 | 保存实际设计点和来源，区分未实现、未编译、未测量与已选择 |

正逆、CT/GS 和顺序变换可以共享依赖结构及组织方法。数值归一化、
旋转因子/模域、排列和精度仍需分别验证，不能以“同构”为由省略实现。
需要转换的路径属于支持方式之一，其完整开销计入调用，原生与适配结果
分别标注。缺少实现时报告缺口，不降精度、升精度、缩小 batch 或替换运算。

FFT 的 benchmark 与对照按 `fft-h`、`fft-l` 两个计算类型组织，底层仍是
同一 `fft` 算子和公共搜索框架。`fft-h` 的输入存储与核心算术采用
FP32/FP64；`fft-l` 包括 FP16/BF16 输入，以及显式采用低精度乘法、较高
精度累加的混合模式。低精度输入即便内部用 FP32 计算也保留在 `fft-l`，
并注明实际路径。FP32 输出不代表乘法也是 FP32。每条记录保留存储、
乘法和累加精度、转换与缩放；分类不授权改变这些语义。TF32 等尚未接通
的模式可登记为候选，不冒充已有支持。两类分别比较匹配精度的外部实现，
不混算加速比，也不将端到端卷积库当作同语义完整 FFT 基线。

局部算术能力和组织方法互相配合。高性能核心应能接入公共空间，较弱
核心也应能作为合法实例验证组织收益。完整外部库若未暴露可隔离的
局部核心，只能作为外部基线；调用该库不等于把其内部核心移植进模板。
若外部库提供可隔离的单轴或子变换接口，可以作为计算核心 provider 接入，
由我们的调度器继续负责其他轴、布局和边界。须记录实际 provider、支持域、
额外存储与转换成本，并区分核心替换收益与固定核心的组织收益；不要求所有
核心均由本项目设计。

**优先复用成熟核心，研究重点是组织方法。** 遇到局部核心性能不足或某个
参数组合没有实现，先检查已有核心的接入、参数枚举和支持域，再引入可复用的
外部核心或其设计策略。不得仅为填满低层参数的笛卡尔积就另造算术核心。
用户的精度、方向、点数、batch 和排列是语义约束；EPT、线程数和核心选择是
映射选项。自动搜索可以选择同一语义下其他合法核心配置，显式 mapping 重放则
必须保持指定配置，不能静默替换。某个 provider 缺少某个 EPT 不等于算子缺失。
新增自研核心需要单独说明必要性和证据，不能默认成为补齐能力的第一步。

吸收外部核心设计的目标是可复用的**模板与参数**：将有效的局部算术、
线程协作、独立线分组、系数供给、交换布局等策略归入 `P/L/F`，保留与
`A` 组织参数的合法组合。接入 provider 是可执行的复用路径，但不等于
已经将其内部设计移植为本项目模板。两种状态分别记录；不能以已有 provider
为由停止必要的策略吸收，也不能只为应用名称添加固定赢家。

模板的参数定义、候选枚举、合法性检查、生成/分派、实际 mapping、缓存与
校准身份必须贯通。不消费的参数不能伪装为可调维度；已实现但没有进入
公共候选的组合应登记并补齐。有限预编译或搜索预算与理论自由度分开报告。

**所有算子遵循同一候选约束流程。** 对完整语义请求，联合构造分段、子图
形状、并行度、时间复用、布局、核心和缓冲组合，再应用依赖、核心支持域及
硬件资源约束。某个大 tile 与深缓冲的组合不可行，只排除该组合，不能据此
排除缓冲机制，或固定 tile 后悄悄关闭机制。更小 tile、更少并行子图和不同
合法分段仍应按声明预算保留。算子投影提供语义与核心能力，不另定一套资源规则。

已知资源下界超过容量时，应在编译和测量之前拒绝。静态检查通过只意味着
满足已知必要条件，寄存器、核心 scratch 和静态 shared 未知时仍需编译后的
资源验证；不能标成已证实可执行。搜索、安装校准、安装后调优和受控实验
应消费一致的合法性合同。有限实验可以固定部分维度，但须先验证全部组合，
并说明未覆盖的其他合法组合，不能将手工实验子集当成框架的完整设计空间。

预编译范围是安装成本选择，JIT 是实现获取方式，二者不定义理论空间。
不得把尚未编译的候选说成方法不支持，也不能把尚未 lowering 的配置
说成 JIT 已经能够生成。

## 3. 校准、调优与实际调用

目标链路是硬件检测与安装校准提供能力和服务代价，生成器构造合法候选，
选择器利用模型及可用实测选择设计点，安装后 tuning 在指定预算内精调，
最终公共调用复用兼容结果。轻量安装与更充分的后续调优属于不同预算，
不得把轻量校准描述成穷尽全部负载。

**平台事实先持久化，公共流程再消费。** 安装或手动 profile 生成硬件容量、
实测服务代价与模型文件，编译阶段保存实际核心资源。候选生成、约束及成本
评估复用这些有版本和来源的静态输入，不为每类蝶形重复采集或散落硬件型号
分支。默认优先使用兼容的本地文件，其次仓库预置文件；更新已有文件须显式
请求。容量、性能样本、模型验证、核心可执行覆盖分别报告，旧的部分 profile
保留部分状态。运行时设备身份和启动安全检查仍需保留，不能以静态文件为由
跳过。具体决策与当前实现边界见 [ADR 0001](adr/0001-static-profile-driven-planning.md)。

- 记录每条选择路径实际消费了哪个 profile、registry 或 cache，以及预算、
  模型/构建身份、候选覆盖和选中 mapping。目录中存在校准文件不等于路径已接入。
- 允许明确标注的未校准估计和预算回退。不能把静态回退、手工 mapping
  或首次测量称为命中已调优结果；要求缓存重放的实验在未命中时应停止该项。
- 安装后 tuning 更新的结果须由公共调用可复用，兼容性涵盖语义、硬件、
  构建与策略。未接通的路径记录为工程缺口，不能反复归因于“再校准即可”。
- 校准与搜索成本单独报告，不计入稳态算子延迟；需要首次调用成本时另列。
  校准是实现手段，不能替代统一方法及性能贡献的论证。
- 开发迭代中，用户授权后可跨构建复用同硬件、同语义、同测量协议的旧数据
  作为模型与搜索先验，保留原始来源并补测新增或失效配置，最终入选方案用
  当前构建确认。版本尚未稳定时不以发布级数据一致性阻塞继续实验，也不因
  全局构建标识变化而机械重测全部旧点；旧数据不改写为当前构建的新实测。

## 4. 三类主实验

### 算子横评

使用一张统一表。一行是完整语义请求，每个高性能对照库独立一列，列
绝对延迟；同时提供加速比、吞吐及误差。维度由算子、精度、方向、输入
输出顺序、各轴点数、rank、batch、布局、归一化等组合，不把这些拆成
无法对齐的特例类别。有限采样矩阵须说明范围及缺口，不宣称穷尽所有组合。

对外表使用公共生成与选择路径的实际方案。手工固定点仅用于解释机制，
不能代表自动库整体表现。精度、布局适配及必需拷贝计入完整调用。
无匹配 GPU 实现时可增加 CPU 对照，但另标平台与边界，不混入 GPU 库
加速比均值。无对照、未完成或不支持均保留，不能记作胜出。

每次性能报告同时给出实际设计点概要：大阶段数量与划分、逐阶段 tile
尺寸、逻辑子图分组和线程配置、连续消费数量、流水范围与深度、计算核心
和布局交接。概要从实际 mapping 与执行实现取得，不能只抄请求参数。
逻辑并行度、launch 的 CTA 数和实测驻留度分别标注；外部黑盒内部结构未知
时明确写未知。统一格式见 [报告合同](reporting_contract.md#设计点概要)。

主性能验证以中大型点数及有限的 batch 扫描为主，检验分层组织的复用、
并行度和扩展性。小尺寸保留为边界检查及真实应用请求，不能把已测负结果
删除。新增主集合独立标识，不能与旧集合混算后声称版本加速。每类算子的
合法点数、数值范围和对照支持域仍需核查，不能只按同一 N 机械复制。

单段路径已经消除了跨段交换，若仍落后，应分别检查局部核心、线程组织、
内存访问和调用边界。确认缺少高效核心时，通过公共核心能力接口增加候选，
不为小尺寸强行增加分段，也不以单段已经存在证明核心已经最优。
“无外部对照”须有查证记录：GPU 库、CPU 库及作者开源实现均要核对；
不兼容的模数、排列或结构化权重不能默认为支持。自写参考实现只验证正确性，
不冒充外部高性能库。

### 机制消融一：组件与自适应选择

固定其他条件改变一个组件，用普通运行时间和硬件统计解释因果关系。
另做**关闭该组件后重新搜索**的受限空间对照，以相同预算和候选验证
协议评估完整方案。两类实验分别回答组件如何起效、选择器如何组合机制。
实际改变多个参数时列出全部变化，不伪装成严格单变量实验。

先冻结典型中大型请求、随机种子、输入、构建及核心，再逐项改变机制。
典型点用于因果诊断，公共库横评仍走自动选择；两者不能互相替代。
每一对保存实际 mapping 差分及唯一允许变化的字段集合，发现隐含变化
则停止该对的单变量归因。单机制主效应之外另测有依据的交互项，不把
累积开启多个组件的瀑布图当成每个组件的独立贡献。

报告延迟、kernel 数、读写/交换量、寄存器、shared 冲突、活跃度和等待
等与假设相关的指标。未采集指标保留空缺；比例按 kernel 记录，不简单
平均。NCU kernel 计数与 memcpy 等完整调用事件区分，profiler 下的时间
不代替普通运行时间。故意欠填充的实现只能作诊断，不能作为强对照。

某机制变慢时核验自动选择是否避开它。完整集合的已测最佳值不差于其
子集只是集合关系；有效证据是实际有限预算搜索选出的方案及其独立复测，
还应保留候选遗漏、排序和选择 regret，而非以候选更多本身证明贡献。

### 机制消融二：固定核心的组织收益与跨核心复用

这是验证运行模板贡献的关键实验，适用于所有蝶形类型。对每一种具备
可替换核心的算子，建立下面的交叉表；缺少第二核心时明确记录工程缺口。

| 局部计算核心 | 原有或匹配的常规组织 | 我们的分层混合组织 | 同核心组织收益 |
| --- | --- | --- | --- |
| 核心 A | 完整调用延迟 A0 | 固定核心 A 后搜索组织得到 A1 | A0/A1 |
| 核心 B | 完整调用延迟 B0 | 固定核心 B 后搜索组织得到 B1 | B0/B1 |

这里的“固定核心”需要可核验的算术实现、精度、局部算法/radix、系数
策略和代码身份。两列保持相同用户语义和输入；组织参数可按声明变化，
但不能同时换用另一个更快核心再把全部收益归给组织。核心可用范围
不同则取真实交集并报告范围，缺格不拿别种算子或精度代跑。

优先使用核心已有的合法原生组织。若只能构造匹配的常规组织，必须如此
标注并保证合理并行度，不能称为该外部库原生性能。同时保留一个受控
组织对照及按同等预算优化后的对照，区分机理归因与实际可获收益。

沿同一行比较说明同核心组织收益，沿同一列比较说明核心影响；在多个
核心及多个蝶形实例上重复，才支持模板可以复用的主张。核心替换可能
改变最佳组织，允许这种相互作用。只比较“我们最快核心+全部机制”与
“对方弱核心”无法单独完成此论证；仅 core×overlap 也只是局部子实验。

**减少复制、排列和独立缩放本身可以是组织收益。** 当这些减少来自生产者
直接写入消费者所需布局、缓冲区所有权安排、驻留复用或合法的尺度融合，
且保持相同语义、精度和输入输出边界，就属于本方法的预期效果。无需要求
核心算术时间也下降才能确认完整调用获益。归因实验保持核心不变，并记录
实际删除/融合的操作及流量；接口约定不同、漏算必要输出或无关归约实现
差异不能混入该归因。

### 应用端到端

端到端汇总表统一使用「场景｜类型｜对照｜加速比」。场景注明应用、输入、
batch 及执行模式；类型指实际使用的蝶形算子，如 FFT、FWHT、NTT，可补充
精度和维度，混合应用列出实际类型。每个对照独立一行，加速比为对照的
完整调用延迟除以 cuButterfly 的完整调用延迟。依照库的 Graph 执行优化，
CUDA Graph 为支持固定形状重复执行的应用的主对比模式，所有对照同样
捕获完整应用。普通调用作为集成诊断保留，不能与 Graph 混比；捕获不支持
时明确列缺口，不回退后冒充 Graph。阶段诊断明确标注，不冒充完整应用。
优先开源典型应用，覆盖不同蝶形类型即可，不为增加数量重复相似应用。
使用真实独立数据的 batch，
保留 B=1 并设置有限的中/大 batch，所有后端使用相同 batch、模型和输入。

配套明细保留整批延迟、吞吐和每样本摊销时间，计入真实的转换、padding、排列、
频域操作、分配与集成开销。数据驻留和拷贝边界对齐并注明；重复调用
单样本不冒充批处理。随机权重可用于性能与实现一致性，不能证明模型质量。
算子加速不能推算应用加速，应用瓶颈或负结果必须独立报告。

应用选择兼顾真实代表性与蝶形计算占比。优先完整变换主导的计算流程，
在测量前固定负载，再用完整调用的 kernel trace 核实占比。不能用孤立算子
时间除以应用时间冒充占比，也不能把基线的非蝶形弱项归因于数据流收益。
Graph 验证必须覆盖不同输入、恢复原输入和返回值生命周期；静态地址不代表
允许固定数据或返回被下一次回放覆盖的结果。缓存固定模板/滤波器时各后端一致。

padding 由应用和算法支持域共同决定。完整应用对照允许各后端使用合法的
自身方案，同时增加相同 padding、相同 xD 形状的直接算子对照来定位差距。
报告有效数据和实际变换数据量；分项诊断与未插入分段同步的完整调用计时
分开，分项时间相加不能替代实测端到端时间。真实应用中的短变换、大 batch
不能用长变换单测的加速比代替。

## 5. 执行、证据和结论

CPU 输入、参考结果、配置和可提前完成的编译尽量先准备，GPU 用于必要
测量；动态产生的新候选另记准备成本。按 UUID 隔离 GPU，有独立 GPU 时
可并行有限任务。可复用的已完成工作不重做，代码改变只扩展相关验证。

整数与 NTT 逐元素精确验证。浮点主参考采用相同存储精度、计算精度和
归一化语义的 CPU 实现；外部 GPU 库是对照，不当作数值真值。低精度
算子的累加和写回舍入位置也须一致，不能用隐式升精度的 NumPy FFT
冒充同精度参考。更高精度结果仅作可选诊断，不额外提高请求的验收要求。
浮点保留完整误差分布及参考库误差，按用户
已选口径报告，不暗设或失败后放宽阈值。用户明确批准的应用阈值继续
按其范围使用。原始压力输入与缩放输入分别标注，所有对照使用同一输入。

结果按版本、硬件、完整语义和协议关联。失败、冲突、未完成、静态回退
与正常测量分开，复用需身份匹配。旧版本方法证据可以引用，但不能当作
当前构建速度；新旧或不同设备的数值不得混算。

结论按算子及负载分层给出配对分布、几何均值、胜率和弱势区间。不得
通过事后只扩展优势样本、混合不同竞品均值或删除负结果支撑“全面领先”。
新增范围应有应用依据，完整保留旧集合并单列新集合。

一次性能负结果可以完成该次实验，不触发无界搜索。后续按既定研究阶段
推进；重大语义选择或无法判断的取舍交给用户，已有授权不重复审批。
“已表达、已生成、已验证、已测量、已接入公共选择、已达到性能目标”
分别记录，不能相互替代。
