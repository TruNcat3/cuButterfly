# 静态选型准备开销修复（2026-11-08）

本轮处理首次 DEFAULT 选型的 CPU 准备成本。前轮十个 FWHT 请求的准备共 2591.758 秒，已与 GPU 稳态计时分开。这里保留原候选、模型公式、合法性检查、排序规则和 finalist 预算，比较相同请求的完整排序及实际选中配置。

## 原因与修改

N256 B1 的公共候选数为 30,146，N4096 B32 为 371,848。候选生成之后，每个描述重复保存一份展开的 mapping 和一份转义的 mapping 字符串；Python 又重复解析与深复制这些字段。各候选中的相同局部几何和硬件调度开销也被重复计算。大候选集把这些小开销累积成了分钟级准备时间。

修改落在公共路径，不按算子、尺寸或 GPU 型号指定赢家：

- `src/plan_registry.cpp` 的两类配置适配器仅传输一份完整 mapping 对象，语义字段与执行组仍完整保留。现有 ranker 合并规则恢复原有效输入，顶层语义字段继续优先。
- `scripts/rank_static_candidates.py` 只解码 mapping 一次。归一化采用顶层复制，单 chunk 视图另复制需要修改的 mapping；输入请求不会被修改。`PreparedPredictor.prepare()` 仍保留独立深复制快照。
- `scripts/stage_cost_model.py` 在单个 predictor 的固定硬件 profile 内，按完整实参复用硬件调度与共享运算几何。各预测返回独立的可变容器。资源异常、primitive 身份、浮点计算顺序、参数覆盖和稳定排序不变。

未删去设计点、忽略资源约束、改变精度或提高测量预算。安装模型与 measured registry 的身份检查也保持不变。此次优化不更换计算核心，不预期产生新的 GPU kernel 加速比。

## 验证范围

CPU 回放使用已保存的 A100 80GB 容量描述。独立诊断程序拦截设备信息查询，隐藏 CUDA 设备，复用旧库的候选枚举和投影；此流程没有 GPU 测量。它重建两个相同 N/B 的正向 FP32 请求，采用默认连续布局（`batch_stride=0` 表示紧密排列），并非截取公共调用的临时文件。候选数与公共记录一致，两种传输表示还原后逐候选比较全部字段，随后分别运行旧、新 Python 排序实现，比较完整输出而不只检查第一名。正常前端调用另由下面的三请求检查验证。

旧实现源码固定于 Git 提交 `819cf566c26401de9a70242de2b5921fda339bf9`。最初一次名为 before 的诊断误用了已包含并行修改的脚本快照，已单独标注，只用于请求表示对比；正式旧版回放重新从该提交提取代码，原诊断文件未覆盖。

198 项相关 Python 测试和 C++/Python 排序桥接测试通过。测试包括 FFT、FWHT、NTT、两种 zeta 与 structured 的请求表示一致性，prior/validated/部分覆盖/无 profile，资源拒绝、稳定并列顺序，以及输入、预测输出和 profile 变化的隔离。

三请求公共 DEFAULT 检查使用原 N256 B1、N4096 B32、128×128 B4 正向 FP32 输入与同精度 CPU 参考，分别记录准备时间、实际 mapping 和两种输出接口的完整 Graph 调用。该有限检查不代替全量横评；计时仍排除编译、准备与 CPU 验证。

## CPU 回放结果与剩余开销

| FWHT 请求 | 候选数 | 旧 CPU 时间 | 新 CPU 时间 | 时间减少 | 请求字节减少 |
|---|---:|---:|---:|---:|---:|
| N256 B1 | 30,146 | 20.012 s | 17.583 s | 12.1% | 20.8% |
| N4096 B32 | 371,848 | 375.234 s | 321.388 s | 14.4% | 17.1% |

时间包含读取/解析、排序计算和结果写出，不含候选构造、GPU 初始化或执行。每侧一次独立进程，共享主机，不据此给出置信区间。两组完整排名输出均逐字节一致，包括预测数值、类别、原因和稳定并列顺序。较大请求的排序计算部分由348.094秒降至296.837秒；进程最大RSS由约7.49GiB降至6.91GiB。请求仍有约2.48GiB，首次准备远未达到轻量级。

对小请求均匀取1000个真实候选做独立CPU trace，当前1.592秒的profile时间中，`PreparedPredictor.prepare()`累计1.338秒，深拷贝累计0.777秒，`stage_terms()`累计0.559秒。资源检查和primitive标识构造各约0.24秒；累计时间互相包含，不能相加为总时间，也不能替代无profile计时。这表明剩余热点仍在逐候选描述处理，尚不能说准备瓶颈已经解决。后续应在明确不可变数据或即时评分生命周期后继续减少快照与特征重复处理，保留当前输入隔离和全部候选验证。
