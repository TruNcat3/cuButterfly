# v0.6 Implementation Status

## Release Scope

v0.6 extends the power-of-two kernel research artifact into a general-shape,
CUDA-library-style plan system. The release keeps operator arithmetic,
architecture mapping, physical processing units, composition boundaries, and
runtime selection as separate objects:

```text
operator contract
    -> exact or embedded shape lowering
    -> per-axis (Ud,Td,Us,Ts) mapping
    -> generated/imported processing unit
    -> boundary residence and output layout
    -> static, cached, measured, or explicit selection
```

This separation is the implementation form of the research claim. Direct
cuFFT, cuFFTDx, Hybrid2D, and register codelets are processing-unit candidates;
using one does not transfer ownership of the surrounding shape, layout,
workspace, logging, or selection contract.

## Implemented Surface

| Area | Implemented in v0.6 |
|:--|:--|
| C plan API | handle, immutable descriptor-derived plan, stream, caller workspace, asynchronous execution, status codes, selection queries, logs |
| exact lengths | packed FP32/FP64 FFT through direct cuFFT or Bluestein; uint64 NTT through modular Bluestein when roots exist |
| embedding | next-power-of-two zero extension for every public operator, with asymmetric forward/inverse logical and physical extents |
| rank two | per-axis FFT, NTT, FWHT, subset/superset zeta, and Structured 2x2 with tiled transpose boundaries |
| selection | exact V100 application profiles, exact-key user cache, bounded `MEASURE`, explicit algorithm IDs, auditable miss logs |
| composition | selected physical axes, selected Bluestein NTT core, direct physical output, and selected fused input |
| generator | warp-register FWHT/Structured boundary-aware variants and existing generated FFT processing units |

The C++ `ButterflyPlan` remains the power-of-two physical-plan API. The C plan
API owns general-shape composition and should be preferred by applications that
need exact arbitrary length, embedding, rank two, or automatic composition
selection.

## Boundary Lowering

The implementation does not assume that every boundary should be fused.
Contiguous physical output removes the final scatter for rank-one embedding
and makes the final rank-two transpose land in caller storage. Strided output
retains scatter semantics.

Forward FP32 FWHT with a generated warp-register unit additionally consumes
the logical input directly and synthesizes the zero tail in registers. It is a
single-kernel, zero-composition-workspace path and is reported as
`+direct-output+fused-input`. Structured 2x2 has a functionally correct
generated fused-input candidate, but the V100 measurement was slower than the
pack path, so the default selector does not enable it. This negative result is
part of the selection methodology: legal fusion is a candidate, not a rule.

## V100 Evidence

The matching-protocol ten-shape power-of-two matrix reports 2.349x geometric-
mean speedup from searched mappings over the fixed radix-2 base and 1.109x
geometric-mean throughput over the matched cuFFT, Dao FHT, and GPU-NTT rows.
That result is representative, not universal.

The v0.6 composition follow-up records:

| Workload | Selected result | Interpretation |
|:--|--:|:--|
| exact FP32 FFT `N=1000,batch=64` | 0.00427 ms, 0.998x matching cuFFT | direct vendor unit selected at parity |
| exact rank-2 FP32 FFT `30x50,batch=64` | 0.00981 ms, 1.000x matching cuFFT | rank-2 direct vendor unit selected at parity |
| uint64 NTT `N=5419,batch=64` | 0.21323 ms | modular Bluestein reuses Hybrid2D radix-4; no exact external baseline is archived |
| embedded FP32 FWHT `32767 -> 32768,batch=256` | 0.11759 ms | complete logical-input path is within 1.01x of the archived 0.11643 ms pre-padded Dao core |
| embedded FP32 FWHT `255 -> 256,batch=65536` | 0.16511 ms | fused input is 2.50x faster than the direct-output pack composition |

Raw rows and protocol details are in [General-Shape V100 Selection
Results](general_shape_results.md). Power-of-two library claims remain governed
by the matching-protocol reports linked from [Experimental
Results](experiments.md).

## Validation

- 49 CTest entries pass on V100/CUDA 11.8.
- C API tests cover exact, embedded, rank-two, strided fallback, cache, and
  forward/inverse contracts.
- Direct processing-unit tests cover zero-extended warp-register FWHT and

  application-profile generation are part of CTest.

## Claim Boundary

v0.6 does not establish universal superiority over specialist libraries or
cross-generation transfer. Exact FFT parity obtained by selecting direct
cuFFT is evidence that the composition can abstain to an appropriate unit, not
that a wrapper makes cuFFT faster. Exact arbitrary NTT depends on the finite-
field root domain. Rank-two execution retains a global transpose because
ordinary CTAs do not provide a conventional in-kernel grid barrier.

The checked-in automatic table is V100-specific. An unseen workload or GPU
uses a legal static fallback, emits a profile-miss log, and can be measured and
cached. Cross-GPU profile capture remains future work; the next research step
is broader fixed-GPU regime mapping over numeric contract, length, batch,
stride, direction, placement, coefficient policy, and boundary residence.
